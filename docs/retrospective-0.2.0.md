# SSH Editor 0.2.0 회고록

작성일: 2026-11-14

## 작업을 이어받은 방식

Claude Code의 인계 문서와 CLAUDE.md를 먼저 읽고 구현된 범위·기존 실패·실행 미검증 항목을 구분했습니다. 이후 대용량 파일 실행 검증부터 진행하고, 상태바 통계와 인코딩 요청을 추가 구현했습니다. 커밋하지 말라는 최초 지침을 유지하다가 사용자의 0.2.0 커밋·푸시 요청에 따라 릴리스 문서를 정리했습니다.

## 효과가 있었던 점

- 약 205MB·100만 줄 파일을 사용한 실제 실행에서 정적 타입 검사로 드러나지 않는 마지막 줄 잘림과 원본 보기 탭 대체 문제를 찾았습니다.
- 재색인 중 이전 읽기 요청이 끝나는 경합을 확인하고 누락 블록을 다시 요청하도록 했습니다.
- 저장 실패·외부 변경·닫기 취소를 테스트해 편집 내용이 유지되는 조건을 명확히 했습니다.
- 인코딩은 표시뿐 아니라 저장·재읽기·충돌 처리·메모리 복원까지 연결했습니다. 표현 불가능한 문자를 거부해 손실 변환을 막았습니다.
- 국내 인코딩 우선 배치와 기타 인코딩 구분·검색을 적용하고, 목록의 모든 항목을 백엔드가 지원하는지 교차 테스트했습니다.
- 통계는 커서 이동 때 파일 전체를 다시 세지 않고 줄별 결과를 재사용합니다. 선택 통계 우선 표시도 폭 계산 테스트로 확인했습니다.

## 아쉬웠던 점과 원인

기능이 여러 층에 걸쳐 변경됐지만 초기 프런트 테스트의 IPC 모의 객체는 이전 인터페이스에 머물러 있었습니다. 실제 스토어를 사용하는 테스트를 갱신하고 새 저장·읽기 인코딩 경로를 검증했습니다. 앞으로 IPC 응답 형식 변경 시 테스트 모의 객체도 같은 변경에 포함해야 합니다.

프런트 번들을 다시 만드는 동안 Rust 검증을 병렬로 실행해 Tauri가 포함하려는 자산이 일시적으로 사라진 실패가 있었습니다. Tauri 검증은 `npm run build` 완료 후 순서대로 실행해야 합니다. 병렬 실행은 자산을 공유하지 않는 테스트와 읽기 작업에 한정하는 편이 좋습니다.

최종 버전을 0.2.0으로 변경할 때 잠금 파일의 문자열을 일괄 치환해 일부 의존성 버전까지 변경한 오류가 있었습니다. 기존 잠금 파일의 패키지·체크섬과 비교해 의존성 버전과 참조를 복원하고 앱 패키지 버전만 갱신했습니다. 버전 수정은 패키지 이름과 필드 범위를 지정하고 잠금 파일 차이를 확인해야 합니다.

후반에는 Windows Computer Use 네이티브 파이프 연결 실패가 반복됐습니다. 재시도와 세션 초기화 후에도 복구되지 않아 새 상태바·인코딩 화면은 실제로 검증하지 못했습니다. 도구 실패를 기능 성공으로 간주하지 않고 작업내역서에 한계로 남겼습니다.

진행 중 문서화 질문을 일본어로 보내 사용자의 한국어 요구를 어긴 일이 있었습니다. 즉시 한국어로 설명하고 질문을 다시 제시했습니다. 이후 질문·진행 안내·문서는 한국어를 유지했습니다.

## 다음 작업에서 개선할 점

1. 상태바의 넓은 화면·최소 폭·다중 선택·분할 편집을 실제 앱에서 검증하고, 인코딩 재읽기·변환 실패 화면까지 확인합니다.
2. CP949·UTF-16·기타 인코딩의 로컬·실제 원격 파일을 같은 내용으로 저장·재읽기해 바이트 수준의 결과를 비교합니다.
3. 기존 Windows 경로 정규화 테스트 실패를 별도 수정하고 기본 테스트를 모두 통과하도록 정리합니다.
4. 보관/해제의 탐색기 다중 선택과 오류 복구, Windows 설치·업그레이드를 실제 환경에서 확인합니다.
5. 릴리스 검증은 프런트 빌드 → Rust 검사·테스트 순서를 고정하고, 실행 검증과 자동 테스트 결과를 계속 구분합니다.

기능별 구현과 검증 범위는 [0.2.0 작업내역서](work-log-0.2.0.md)를 참고하세요.
