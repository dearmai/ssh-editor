## 1. SFTP 차단 서버 및 통합 테스트

사용자 요청에 따라 SFTP 세션 수 제한이 아닌 **SFTP 서브시스템 자체를 허용하지 않는** OpenSSH 서버를 Podman으로 구성했습니다. SSH 셸·exec·PTY는 허용하고 `Subsystem sftp`는 설정하지 않았습니다. 호스트 포트는 로컬 주소 `127.0.0.1:22222`에만 바인딩합니다.

`tests/ssh-no-sftp/`에 컨테이너 설정과 재현 방법을, `src-tauri/src/ssh/no_sftp_tests.rs`에 실제 서버 대상 테스트를 추가했습니다. 일반 테스트 실행에는 포함하지 않고 `--ignored`로 명시 실행합니다.

- 접속 후 SFTP 초기화 거부 및 셸 파일 접근 방식 선택을 확인했습니다.
- 파일 8개를 동시 요청으로 생성·열기·수정·저장하고 재읽기 결과와 바이트 크기를 비교했습니다.
- 한글·공백·작은따옴표 파일명과 UTF-8 내용을 확인했습니다.
- PTY 3개가 열린 상태에서 파일 저장·읽기·서버 ping을 확인하고, 네 번째 PTY 추가 및 파일 읽기를 확인했습니다.
- 터미널을 닫은 뒤 파일 읽기와 새 PTY 생성 및 명령 응답을 확인했습니다.
- 테스트 계정 비밀번호 인증을 재확인했습니다. 접속 정보는 [테스트 서버 안내](../tests/ssh-no-sftp/README.md)에 있습니다.

이 테스트는 기존 셸 대체 구현을 실제 서버에서 검증한 것으로, SFTP 대체 기능을 이번에 새로 구현한 것은 아닙니다. 초기의 추가 제한 `MaxSessions 4`에서는 동시 요청이 채널 한도에 도달했습니다. 최종 설정은 SFTP만 차단하고 SSH 채널 한도는 기본값 10개를 사용합니다.

## 2. npm 보안 경고 조치

최초 감사 결과는 8건(보통 2, 높음 5, 치명적 1)이었습니다. 호환 범위 내 의존성 갱신 후 남은 Monaco 하위 DOMPurify 문제도 실제 배포 코드에서 제거했습니다.

| 대상 | 조치 |
| --- | --- |
| DOMPurify | 직접 의존성 최소 버전을 3.4.17로 변경, 하위 의존성도 동일 버전 사용 |
| Vite | 최소 버전을 6.4.6으로 변경 |
| Monaco | 0.57.0을 직접 의존성으로 지정, 사전 빌드 파일 복사에서 ESM 소스 번들로 전환 |
| Monaco 정화 코드 | Vite alias로 내장 구버전 모듈을 수정된 npm DOMPurify로 교체 |
| 배포 검증 | 내장 구버전 모듈 유입 및 수정 모듈 누락 시 빌드 실패 처리 |
| 오프라인 사용 | 편집기 및 JSON·CSS·HTML·TypeScript 워커를 로컬 번들에 포함 |

`scripts/copy-monaco.mjs`는 제거하고 `src/monaco.ts`에서 로컬 편집기와 워커를 구성합니다. 새 잠금 파일로 `npm ci`를 실행한 뒤 `npm audit` 취약점 0건을 확인했습니다. 감사 결과는 작업 시점의 의존성 및 보안 데이터 기준입니다.

## 3. 비밀번호 보기/숨기기

`PasswordInput.tsx` 공통 컴포넌트를 추가하고 SSH·점프 호스트·프록시 비밀번호 필드에 적용했습니다.

- 입력란 우측 내부의 눈 아이콘으로 표시 상태를 전환합니다.
- 기본 상태는 숨김이며 전환 중 입력값을 유지합니다.
- 버튼에 보기/숨기기 접근성 이름과 상태를 제공하고 키보드 포커스를 표시합니다.
- 마우스로 전환할 때 입력란 포커스를 유지하고 버튼 클릭으로 폼이 제출되지 않게 했습니다.

## 4. Windows 무인 설치

`scripts/install-app.ps1`과 Makefile 설명, Windows 빌드 안내를 수정했습니다.

| 설치 형식 | 실행 방식 | 종료 처리 |
| --- | --- | --- |
| NSIS | `/S`, 숨김 실행, 완료 대기 | 0 성공, 그 외 실패 |
| MSI | `/qn /norestart`, 숨김 실행, 완료 대기 | 0 성공, 3010 성공 및 재시작 안내, 그 외 실패 |

빌드 로그는 유지하며 설치 마법사는 표시하지 않습니다. 설치 스크립트는 자동 재부팅을 요청하지 않습니다. 실패 시 예외를 발생시켜 `make install`에 실패를 전달합니다.

## 5. 버전 및 문서

`package.json`, `package-lock.json`의 앱 버전 2곳, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`의 앱 패키지, `src-tauri/tauri.conf.json`, `scripts/native.sh`를 0.1.1로 통일했습니다. 코드 서명 안내의 설치 파일명 예제도 맞췄습니다.

루트 `CHANGELOG.md`에 버전 수정 내역을 작성하고 README에서 두 문서로 연결했습니다. 작업내역서가 Git에 포함되도록 `.gitignore` 예외를 추가했습니다.

앱 메뉴의 `SSH Editor → 버전 수정 내역`과 하단 `v0.1.1` 버튼에서 여는 변경 이력 대화상자를 추가했습니다. 저장소의 `CHANGELOG.md`를 빌드에 직접 포함해 오프라인에서도 같은 내용을 표시하며, 버전 표시는 `package.json` 값을 사용합니다. 긴 내역은 스크롤할 수 있고 닫기 버튼·Escape 키·바깥 클릭으로 닫습니다. 메뉴 이벤트는 현재 포커스된 창으로만 전달합니다.

후속 확인에서 Windows About 항목에 정보 데이터를 주지 않으면 메뉴 라이브러리가 대화상자를 열지 않는 것을 확인했습니다. About 메타데이터에 앱 이름·실제 패키지 버전·작성자·설명을 지정했습니다. 버전 수정 내역 등 창별 메뉴는 현재 포커스된 창을 우선하고, 메뉴 조작으로 포커스가 해제되면 마지막 활성 창, 기본 창, 남아 있는 창 순으로 전달합니다. 다른 창에 대화상자를 동시에 띄우지 않습니다.

| Rust 라이브러리 전체 실행 | 10개 통과, 기존 로컬 파일 경로 비교 테스트 1개 실패 |

SFTP 통합 테스트의 PTY 부분은 실제 SSH 프로토콜과 앱의 연결을 사용하지만 Tauri 이벤트 전달·xterm 렌더링·에디터 저장 단축키까지 검사하지 않습니다. 네이티브 앱 화면 검증은 Windows 자동화 도구의 `failed to activate captured window` 오류로 완료하지 못했습니다. 브라우저 검증은 별도 테스트용 프로덕션 번들에서 수행했습니다.

Windows 설치 프로그램을 실제 실행해 설치/업그레이드하는 검증은 수행하지 않았습니다. 무인 설치 검증은 빌드와 설치 프로세스를 대체한 모의 실행입니다. 설치 권한 요청 등 운영체제 화면까지 제거한다는 의미는 아닙니다.

전체 Rust 테스트에서 실패한 항목은 `local_files::tests::accepts_files_and_urls_but_not_ssh_targets_or_directories`의 경로 비교이며 관련 구현은 이번 작업에서 변경하지 않았습니다. 프로덕션 빌드의 큰 청크 크기 안내는 남아 있습니다.
