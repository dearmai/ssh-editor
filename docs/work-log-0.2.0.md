## 1. 로컬 파일 보관과 해제

ChaCha20-Poly1305와 Argon2id를 사용한 비밀번호 기반 보관/해제를 추가했습니다. 파일은 식별 매직·salt·nonce·암호문·인증 태그로 구성합니다. 설정의 기능 탭에서 활성화와 확장자를 지정하며, 확장자를 비우면 제자리에서 교체합니다.

파일과 폴더를 대상으로 처리하되 루트·시스템·홈 폴더 자체는 차단하고, 폴더 내부까지 펼친 대상이 5개 이상이면 거부합니다. Windows 탐색기 메뉴와 별도 보관/해제 창을 추가했습니다. 탐색기 다중 선택으로 프로세스가 여러 개 시작되면 임시 큐와 잠금 디렉토리로 요청을 모읍니다.

## 2. 대용량 파일과 구간 편집

환경설정에서 로컬·원격의 일반 열기 한도와 대용량 한도를 구분합니다. 기본값은 로컬 50/100MB, 원격 1/10MB이며 상한은 512MB입니다.

로컬 텍스트 보기는 1,000줄마다 바이트 위치를 기록하는 희소 색인과 200줄 블록 캐시를 사용합니다. 캐시는 최대 60블록이며 큰 스크롤 높이는 비율로 줄 위치에 대응시킵니다. 연속·가로 스크롤, 줄 번호 이동, 전체 검색 결과 이동, tail을 지원합니다.

‘이 위치부터 편집’은 최대 5,000줄·8MB의 UTF-8 구간을 별도 탭으로 엽니다. 원본 기준 줄 번호를 표시하고, 저장할 때 앞부분·수정 구간·뒷부분을 임시 파일로 흘려 쓴 뒤 교체합니다. 저장 전과 복사 후에 크기·수정 시각을 검사합니다. 저장 후 보기 화면을 다시 색인합니다.

실행 검증 중 발견한 재색인 요청 경합, 마지막 줄 잘림, 구간 탭 생성 시 원본 보기 탭 대체를 수정했습니다. 탭·다른 탭·패널 닫기에 저장 확인을 연결하고 저장 실패나 취소 시 편집 내용을 유지합니다.

## 3. Hex 보기와 메모리 해제

로컬·원격 파일의 바이트를 16KB씩 읽는 Hex 보기와 파일 트리 메뉴를 추가했습니다. 바이너리·대용량 파일의 열기 선택지를 구분합니다.

수정되지 않은 비활성 편집 탭의 내용을 메모리에서 해제하고 선택 시 다시 읽는 기능을 추가했습니다. 기본 기준은 200MB이며 구간 편집 탭은 제외합니다.

## 4. 상태바 통계와 인코딩

편집기 상태바에 현재 행·파일·선택 영역의 글자 수·바이트 수·단어 수를 표시합니다. 폭이 부족하면 선택 영역을 우선하고 행·파일 통계는 생략합니다. 글자는 공백·줄바꿈을 포함한 유니코드 코드 포인트, 단어는 공백 기준입니다. 바이트는 현재 인코딩 기준이며 파일은 BOM을 포함합니다. 구간 탭의 통계 대상은 열린 구간입니다.

상태바 인코딩을 클릭하면 다시 읽기 또는 변환 후 저장을 선택합니다. 국내에서 자주 쓰는 UTF-8·UTF-8 BOM·CP949/EUC-KR·UTF-16 LE/BE를 상단에 배치하고, 구분선 아래 기타 인코딩 35개와 검색을 제공합니다.

BOM·UTF-8·CP949 순으로 최초 판별하며 자동 판별이 불명확하면 사용자가 직접 지정합니다. CP949/EUC-KR은 호환 문자 집합으로 처리합니다. 선택한 인코딩은 일반 저장·충돌 해결·외부 변경 재읽기·메모리 복원에도 유지합니다. 표현 불가능한 문자는 저장 전에 거부하며 미저장 내용을 재읽을 때는 확인합니다. 변환은 파일 전체 편집 탭에서 수행합니다.

## 5. 빌드와 버전 정리

Windows 설치판은 `build/windows/`, 포터블은 `build/windows-portable/`에 모읍니다. 포터블 빌드 시 대상 실행파일이 실행 중이면 종료 여부를 확인합니다. 한국어 PowerShell 스크립트는 UTF-8 BOM으로 저장합니다. 환경설정 창 높이와 하단 버튼 위치도 고정했습니다.

앱 버전을 npm·Cargo·Tauri 설정과 잠금 파일, 네이티브 빌드 스크립트에 0.2.0으로 반영했습니다. README와 CHANGELOG를 갱신하고 이번 작업내역서·회고록을 Git 추적 대상으로 추가했습니다.

## 6. 검증 결과와 제한

| 검증 | 결과 |
| --- | --- |
| 프런트 타입·프로덕션 빌드 | 통과 |
| 프런트 전체 테스트 | 118개 통과 |
| Rust 타입 검사 | 통과 |
| Rust 라이브러리 테스트 | 35개 통과, 2개 제외, 기존 경로 테스트 1개 실패 |
| 인코딩 테스트 | 한글·BOM 왕복, 손실 변환 거부, 목록 전체 지원, 로컬 실제 파일 교체 통과 |
| 대용량 네이티브 실행 | 약 205MB·100만 줄 파일로 휠·Page Up·50만 줄 이동·가로 스크롤·검색 이동·tail 확인 |
| 구간 편집 실행 | 원본 줄 번호, 실제 저장 결과, 외부 변경 후 저장 거부, 닫기 확인 저장과 보기 갱신 확인 |
| 새 상태바·인코딩 화면 | Windows 화면 제어 도구 연결 실패로 실제 화면 검증 미수행 |

기존 실패는 `local_files::tests::accepts_files_and_urls_but_not_ssh_targets_or_directories`의 Windows 임시 경로 정규화 비교입니다. 레지스트리 테스트와 실제 SSH 서버가 필요한 테스트는 기본 실행에서 제외됩니다. 기존 `russh-keys` 미사용 경고와 Vite 큰 청크 안내가 남아 있습니다.

이번에는 원격 인코딩 변환의 실제 서버 실행, 보관/해제 탐색기 흐름 전체, Windows 설치·업그레이드, macOS·Linux 실행을 새로 검증하지 않았습니다. 자동 테스트 통과와 실제 화면 검증 범위를 구분해 기록합니다. 관련 개선점은 [0.2.0 회고록](retrospective-0.2.0.md)에 정리했습니다.
